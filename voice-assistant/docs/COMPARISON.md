# Сравнение и лучшие практики: Алиса, Siri, Google Assistant, Salute (Сбер)

Документ фиксирует, какие идеи и паттерны взяты из ведущих ассистентов и как они отражены в **Свободном Голосе**. Цель — не копирование проприетарных продуктов, а перенос **принципов** в открытую, локальную и расширяемую реализацию без подписок.

## 1. Обзор по ассистентам

### Яндекс Алиса
**Сильные стороны:** высокий уровень понимания русского языка, разговорность, контекст диалога, большая экосистема навыков, интеграция с умным домом и сервисами, сценарии.
**Что берём:** русскоязычный UX и паттерны команд, модель «навыков» (skills) как расширяемых модулей, поддержка контекста/уточнений, приоритет локальных сценариев (таймеры, заметки, напоминания), дружелюбный тон.

### Apple Siri
**Сильные стороны:** глубокая интеграция с устройством, краткие и предсказуемые ответы, приватность (часть обработки на устройстве), шорткаты/автоматизации, управление приложениями.
**Что берём:** лаконичность ответов, принцип «минимум трения» для частых действий, allowlist/подтверждения для чувствительных операций, режим коротких команд, локальное выполнение где возможно.

### Google Assistant
**Сильные стороны:** сильный поиск и работа со знаниями, широкий охват запросов, рутины, контекст цепочки вопросов, мультимодальность.
**Что берём:** связка «намерение → действие/поиск», graceful fallback (если навыка нет — поиск/LLM), рутины как композиции действий (roadmap), кэширование и устойчивость к недоступности источников.

### Salute / Сбер (Салют)
**Сильные стороны:** ориентация на русский рынок, сценарии, интеграции в экосистему, голосовые персонажи/тональность.
**Что берём:** акцент на русские сценарии и формулировки, сценарный подход к навыкам, возможность смены стиля ответов через конфиг/промпт.

## 3. Архитектурные принципы, доведённые до «продакшен-подхода»

1. **Разделение пайплайна**: `Input (text/voice) → NLU (intent+entities) → Skill/Action → NLG (text) → Output (UI/TTS)`. Каждый этап заменяем.
2. **Детерминированное ядро + опциональный ИИ**: критичные команды (таймер, заметка, калькулятор, управление) работают правилами офлайн; LLM используется как усилитель для свободного диалога.
3. **Graceful degradation**: нет сети — работают локальные навыки и кэш; нет модели — rule-based; нет микрофона — текст.
4. **Переносимость**: минимум зависимостей (stdlib), конфиг-файлы, относительные пути, отсутствие привязки к облаку/аккаунту.
5. **Безопасность по умолчанию**: никаких произвольных shell-команд из пользовательского текста, подтверждения деструктивных действий, секреты вне репозитория.
6. **Наблюдаемость**: статус, структурированные ответы навыков (`data`, `intent`), опциональная история.

## 4. Что нужно добавить для полноценного «уровня продуктов» (честно)

- **Качественный офлайн ASR/TTS на русском**: предустановленные модели (sherpa-onnx/Vosk/Whisper/Piper) + упаковка под целевые платформы.
- **ML-NLU/slot-filling и диалоговый менеджер**: датасеты, обучение/адаптация, память пользователя.
- **Wake-word и VAD**: always-on прослушивание с локальным детектором.
- **Глубокие интеграции**: календарь, музыка, медиа, умный дом по стандартам (Matter/HA API), уведомления.
- **Тестирование на реальных устройствах и голосовых корпусах**, метрики WER/intent accuracy, латентность.
- **Безопасное обновление/распространение** (пакеты, подписи) — вне текущей офлайн-среды.

FreeVoice закладывает каркас и рабочие локальные возможности, чтобы пользователь мог наращивать эти компоненты **без подписок и под свой контур**.
