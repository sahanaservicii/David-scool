# HomeGuard — родительский контроль без облака

Два собственных Android-приложения и локальный протокол. Никаких аккаунтов,
FCM, Google Play, подписок и внешних серверов: управление идёт по домашней
сети или через WireGuard на роутере.

| Компонент | Пакет | Размер | Роль |
|---|---|---|---|
| **Агент** | `ru.homeguard.agent` | ~60 КБ | живёт на телефоне ребёнка, Device Owner (DPC), применяет политику |
| **Консоль** | `ru.homeguard.console` | ~61 КБ | на вашем телефоне, UI + встроенный HTTP-сервер + база |

```
телефон ребёнка                         ваш телефон
┌────────────────────┐   HTTP (LAN/WG)  ┌─────────────────────────┐
│ Agent              │ ───────────────▶ │ Console                 │
│  DPM / политика    │  POST /sync      │  ControlServer :8787    │
│  Scheduler         │ ◀─────────────── │  SQLite: политика,      │
│  Foreground sync   │  policy+commands │          команды, events│
│  Curfew overlay    │  POST /ack       │  UI: устройства, отчёты │
└────────────────────┘                  └─────────────────────────┘
```

Модель **pull**: телефон ребёнка сам опрашивает консоль раз в 60–120 секунд.
Поэтому не нужны проброс портов, push-сервисы и постоянный сокет; работает за
NAT и в Doze, а если консоль недоступна — агент продолжает жить по последней
политике.

## Что умеет (v1)

| Требование | Как реализовано |
|---|---|
| Блокировка приложений | `setPackagesSuspended` + `setApplicationHidden`, список в политике |
| Блокировка установок/удаления | user restrictions `DISALLOW_INSTALL_APPS`, `DISALLOW_UNINSTALL_APPS`, `DISALLOW_INSTALL_UNKNOWN_SOURCES_GLOBALLY` |
| Камера | `setCameraDisabled` |
| Wi-Fi / Bluetooth / USB | `DISALLOW_CONFIG_WIFI`, `DISALLOW_BLUETOOTH`, `DISALLOW_USB_FILE_TRANSFER`; аварийно — авиарежим через `setGlobalSetting` |
| Местоположение | разовый запрос `locate` (GPS/Network, `LocationManager`), без фонового трекинга |
| Экранное время | `UsageStatsManager`, дневной лимит, отчёты по приложениям |
| Расписание / «тихий час» | окна `curfew` по дням недели, проверка раз в минуту |
| Тревоги | событие `sos` с телефона ребёнка → high-importance уведомление на консоли |
| Блокировка экрана | `lockNow()` + полноэкранный overlay в lock task mode, выход только командой |
| Киоск | `setLockTaskPackages` / `LOCK_TASK_FEATURE_NONE` |
| Скриншоты, статус-бар, keyguard, safe boot, factory reset, debug | соответствующие DPM-методы и restrictions |
| Ручная разблокировка | команда `unlock` даёт 30 минут «тишины» расписанию |

## Чего приложение не делает — намеренно

* Не читает SMS, звонки, мессенджеры, фото и пароли. На современном Android это
  требует либо root, либо вредоносных API — и это не «родительский контроль», а
  слежка. Здесь только управление функциями устройства.
* Не показывает экран ребёнка в реальном времени (`MediaProjection` требует
  согласия на устройстве при каждом включении).
* Не работает вне дома, пока не поднят WireGuard на роутере. Push-уведомлений
  без облака не существует: команда доедет, когда телефон выйдет на связь.
* Не обходит «Безопасный режим» и recovery на 100%: Device Owner закрывает
  большинство путей (`DISALLOW_SAFE_BOOT`), но физический доступ к кнопкам
  остаётся.

## Нагрузка

* Один HTTP-запрос раз в 60 с (Wi-Fi) / 120 с (мобильная сеть), тело ~1–3 КБ.
* `HttpURLConnection`, `Connection: close`, без библиотек — 94 КБ APK, ~15–25 МБ
  RSS, без wakelock. Ориентир: 1–2 % батареи в сутки в LAN.
* `UsageStatsManager` и `Scheduler` — дешёвые системные запросы раз в минуту.
* Служба `accessibility` **не обязательна** (по умолчанию выключена): нужна
  только для мгновенного закрытия приложений, запущенных в обход DPM.

## Быстрый старт

1. Собрать (см. `docs/BUILD.md`) или взять готовые APK из `dist/`.
2. Поставить **консоль** на свой телефон, открыть, дать уведомления.
   На экране появится `Сервер: http://192.168.1.x:8787`.
3. «Добавить ребёнка» → имя → получить строку вида
   `hg1:192.168.1.x:8787:kid-ab12:ABCD-EFGH-JKLM-NPQR`.
4. Телефон ребёнка: сброс к заводским настройкам, установить агент, ввести код,
   сделать его Device Owner (`docs/PROVISIONING.md`), включить службу.
5. Настроить политику в консоли. Изменения доезжают до 2 минут.

Статический адрес консоли в DHCP и WireGuard-туннель описаны в
`docs/PROVISIONING.md`.

## Данные и обновления

* **Резервная копия** — «Настройки → Данные»: файл `.hgbak` в «Загрузки/HomeGuard»,
  шифрование PBKDF2-SHA256 (150k) + AES-256-GCM. Пароль не хранится.
* **Восстановление** — тем же экраном: системный выбор файла + пароль.
  Дети, правила и история возвращаются на новом телефоне.
* **Схема БД версионируется** (`Db.DB_VERSION`), обновление APK переносит данные.
* **Ретенция** чистит старое сама: события 120 дней, статистика 400 дней.
* **Лог сбоев** пишется локально, без отправки куда-либо.
* **Тесты**: `sh tools/test.sh` — 34 проверки протокола, без JUnit и сети.

Подробные процедуры — `docs/OPERATIONS.md`.

## Интерфейс консоли

Четыре вкладки, всё локально:

| Вкладка | Что внутри |
|---|---|
| **Главная** | экранное время за день, карточки детей с прогрессом лимита, статус сервера |
| **События** | лента по дням: SOS, блокировки, попытки открыть запрещённое, обновления правил |
| **Отчёты** | график за 7 дней, топ приложений, фильтр по ребёнку |
| **Настройки** | адрес сервера и все интерфейсы, проверка сервера, дети, о приложении |

Экран ребёнка: hero-карточка (модель, батарея, Device Owner), кольцо экранного
времени, четыре быстрых действия, правила, отчёты, код привязки и отдельный
блок опасных действий.

Дизайн сделан вручную на framework-виджетах: ни AndroidX, ни Compose, ни
внешних шрифтов — поэтому APK остаётся около 97 КБ и работает офлайн.

## Интерфейс агента

Агент выглядит как младший брат консоли: та же палитра и те же карточки.

* **Шапка** — статус защиты, прогресс готовности («6 из 9»), время последней
  синхронизации и версия политики.
* **SOS** — большая красная кнопка: сигнал и координаты в консоль одним
  нажатием, без меню.
* **Настройка** — чек-лист: права владельца, привязка, уведомления, геолокация,
  статистика, спец. возможности, overlay, батарея, ADB. Пункт «Нужно» открывает
  нужный системный экран; «Готово» — просто подтверждение. Это же и есть мастер
  первого запуска.
* **Подключение** — поле кода привязки и имя устройства.
* **Диагностика** — Android, модель, ID, сервер, гео, экран за день, блокировка.

Экран тихого часа — тёмный, с крупными часами и причиной блокировки; SOS на нём
доступен, чтобы ребёнок всегда мог позвать родителя.

## Работа в любой сети: Wi-Fi + мобильный

Цель: контроль не пропадает при переключении Wi-Fi ↔ мобильный интернет и при
выходе из дома, а обычный интернет при этом не страдает.

1. **Split tunnel, а не весь трафик.** На обоих телефонах в конфиге WireGuard:

   ```
   AllowedIPs = 192.168.9.0/24      # только домашняя WG-подсеть
   PersistentKeepalive = 25
   ```

   Всё остальное (YouTube, браузер, игры) идёт напрямую через Wi-Fi или
   мобильный — скорость и расход батареи не меняются.

2. **Always-on VPN** на обоих телефонах: Настройки → VPN → WireGuard →
   «Постоянно включённый VPN». Галочку «Блокировать соединения без VPN»
   НЕ ставить — иначе при обрыве туннеля у ребёнка пропадёт интернет.

3. **Два адреса в привязке** — `hg1:192.168.1.x+192.168.9.2:8787:ID:КОД`.
   Дома агент берёт LAN (быстрее), вне дома — туннель. Рабочий адрес
   запоминается, при обрыве берётся второй.

4. **Батарея**: «Без ограничений» для HomeGuard-агента и для WireGuard.
   MIUI иначе выгружает VPN и синхронизацию.

5. **Смена сети**: с версии 1.1.1 агент реагирует на появление сети сразу
   (`NetworkCallback`), backoff не больше 4 минут. События в очереди не
   теряются.

Чего не бывает: если у ребёнка вообще нет связи (ни Wi-Fi, ни мобильного) —
синхронизации нет. Политика при этом продолжает действовать локально, а
события копятся и уходят, когда сеть вернётся.

## WireGuard: работа вне дома

Туннель использовать можно и нужно — он заменяет проброс портов. Консоль слушает
`0.0.0.0:8787`, то есть доступна по любому своему адресу, включая адрес в
туннеле. В привязке можно указать **два адреса через `+`**:

```
hg1:192.168.1.155+10.66.0.2:8787:kid-ab12:ABCD-EFGH-JKLM-NPQR
        ^ LAN, дома          ^ туннель, вне дома
```

Агент пробует тот адрес, который сработал в прошлый раз, и при неудаче
переключается на второй. Если адрес один — можно указать только его.

Что должно быть выполнено:

1. Телефон-консоль и телефон ребёнка — пиры одной WireGuard-сети (или маршрут
   до адреса консоли есть на роутере).
2. `AllowedIPs` на телефоне ребёнка включает адрес консоли (`10.66.0.2/32` или
   всю подсеть `10.66.0.0/24`).
3. На телефоне ребёнка `PersistentKeepalive = 25` — иначе после NAT туннель
   засыпает и синхронизация встанет.
4. На телефоне-консоли WireGuard включён постоянно («Always-on VPN» в Android),
   иначе вне дома её адрес недоступен.

Проверка до всякой установки агента: с телефона ребёнка открыть в браузере

```
http://10.66.0.2:8787/api/v1/ping      →  {"ok":true,"app":"homeguard-console","port":8787}
```

Если ответ пришёл — канал рабочий и привязка точно заведётся.

## Протокол

Все запросы подписаны HMAC-SHA256 секретом устройства; секрет 80-битный,
хранится в Android Keystore (AES-256-GCM), генерируется при привязке.

```
X-HG-Device: kid-ab12
X-HG-Ts:     1700000000            (окно ±300 с)
X-HG-Nonce:  aabbccddeeff00112233   (одноразовый, хранится 600 с)
X-HG-Sig:    HMAC(secret, "POST\n<path>\n<ts>\n<nonce>\nSHA256(body)")
```

* `POST /api/v1/sync` — состояние устройства + `events`; ответ: `policy` + очередь `commands`.
* `POST /api/v1/ack` — результат команды.
* `GET  /api/v1/ping` — проверка живости сервера (без HMAC, только «жив ли»).

Ответы сервера тоже подписаны, иначе агент их игнорирует:

```
X-HG-Ts:    1700000005
X-HG-Nonce: 8c1d4a9b7e3c5d6a1b2c3d4e
X-HG-Sig:   HMAC(secret, "RESP\n<path>\n<ts>\n<nonce>\nSHA256(body)")
```

Политика версионируется (`v`), агент применяет только более новую версию.
Команды идемпотентны по `id` (128 бит) и переотправляются, если ack не пришёл
за 10 минут; ack привязан к устройству. Сервер принимает только приватные
адреса-источники и держит запрос не дольше 15 с. Подробности — `docs/SECURITY.md`.

## Ограничения платформы (Android 13–15)

* `PACKAGE_USAGE_STATS` — доступ к статистике выдаётся вручную один раз.
* `SYSTEM_ALERT_WINDOW` для overlay желателен: DPC обычно может стартовать
  activity из фона, но разрешение убирает различия между прошивками.
* `WifiManager.setWifiEnabled` для сторонних приложений закрыт с Android 10;
  поэтому «выключить сеть» — это авиарежим (`setGlobalSetting`) либо запрет
  изменения настроек.
* Некоторые вендоры (Xiaomi/POCO) убивают фоновые службы агрессивнее: нужен
  пункт «Отключить экономию батареи» и автозапуск.
