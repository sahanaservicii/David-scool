## Главная finding: `192.168.1.191`

| Поле | Значение |
|---|---|
| MAC | `c8:22:02:59:c6:0f` |
| DHCP hostname | `reg` |
| ARP на роутере | подтверждён, `br-lan`, STALE |
| Порты | 80, 554, 34567 |
| HTTP | `200`, `Server: APPWebs/`, title `index` |
| RTSP | `RTSP/1.0 200 OK`, `Server: Topsvision Server v2.1` |
| Подключение | в Wi-Fi assoclist нет — проводное подключение к `br-lan` |

Вывод: неучтённое устройство Topsvision, по баннеру то же семейство, что NVR `.190` («Topsvision reg.lan»). Вендор по OUI не определялся: локальной базы OUI в офлайн-среде нет; вендор установлен по ответу самого устройства.

Применённое действие: firewall-правило `Block-Cam191-WAN` (`src=lan`, `src_ip=192.168.1.191`, `dest=wan`, `proto=all`, `target=DROP`, `enabled=1`). Цель — запретить исходящие соединения (P2P/облако) в интернет. RTSP-просмотр из LAN и доступ к роутеру не затрагиваются.

Откат правила:
```sh
uci delete firewall.cfg1a92bd && uci commit firewall && /etc/init.d/firewall reload
```

## Ограничение

Полная L2-изоляция `.191` от остальных устройств LAN **не применялась**: трафик внутри одного моста `br-lan` не проходит через fw4/IP-правила, а переключение порта в отдельный VLAN несёт риск нарушить работу камеры. Для полной изоляции нужна отдельная VLAN/SSID для камер с последующей проверкой доступа с HA/телефона — это отдельная задача с подтверждением пользователя.
