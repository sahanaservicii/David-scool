# Безопасность HomeGuard

Домашний комплект: консоль на телефоне родителя, агент на телефоне ребёнка.
Сеть — только LAN/WireGuard, без облака и пробросов. Ниже — что закрыто,
что осталось и как это проверить.

## Модель угроз

| Угроза | Реальность |
|---|---|
| Чужой в той же Wi-Fi/LAN пытается управлять агентом | возможен (сосед, гости, IoT) |
| Подменённый сервер по адресу из «кода привязки» | возможен (социнженерия) |
| Перебор секрета | нереален: 80 бит, окно ±300 с |
| Кража телефона родителя | физический доступ = данные консоли |
| Публикация порта в интернет | исключено: пробросов нет, сервер только для приватных адресов |

## Что закрыто (консоль 1.4.0, агент 1.3.0)

1. **Подпись ответов.** Консоль подписывает каждый ответ `200`:
   `RESP|path|ts|nonce|sha256(body)` тем же секретом устройства, заголовки
   `X-HG-Ts`, `X-HG-Nonce`, `X-HG-Sig`. Агент проверяет подпись, окно ±300 с
   и повтор nonce **до** разбора JSON: политика и команды из неподписанного
   ответа игнорируются. Раньше HMAC защищал только запросы, и подменённый
   сервер мог прислать `wipe`.
2. **Привязка только к домашней сети.** Агент принимает в коде привязки
   исключительно IPv4 из `10/8`, `172.16/12`, `192.168/16`, `127/8`,
   `169.254/16` — публичный адрес или доменное имя отклоняются. Перед
   сохранением показывается подтверждение с адресом консоли и ID устройства.
3. **Сервер не отвечает публичным адресам.** `ControlServer` закрывает
   соединение, если источник не приватный (RFC1918, loopback, link-local,
   IPv6 ULA), и это до чтения запроса.
4. **Лимиты запроса:** тело ≤ 64 КБ, ≤ 32 заголовков и ≤ 16 КБ на них,
   строка ≤ 4 КБ, абсолютный дедлайн 15 с от accept до ответа, короткое тело —
   ошибка. Четыре медленных клиента больше не вешают синхронизацию.
5. **Nonce:** длина 16–64 hex, кэш ≤ 10 000, TTL 10 минут, вставка атомарная;
   при переполнении — отказ, а не рост памяти.
6. **Команды привязаны к устройству.** `ack` обновляет строку по
   `id AND device`, ID команды — 128 бит вместо 32.
7. **Валидация данных:** `min` экранного времени ограничен 0…1440, `LIMIT`
   в SQL — параметр, а не конкатенация.
8. **Экран кода привязки** помечен `FLAG_SECURE`: скриншоты и превью в
   «Недавних» не содержат секрет.
9. **Логов нет:** ни `android.util.Log`, ни `printStackTrace` в коде
   приложений; `allowBackup="false"` в обоих манифестах; exported-компоненты
   защищены `BIND_*`-разрешениями; deeplink-фильтров нет.
10. **R8 включён** в релизах: `minifyEnabled` + `shrinkResources`, entry-классы
    сохранены, reflection в коде отсутствует.

## Остаточные риски (приняты осознанно)

| Риск | Почему оставлен | Что сделать, если станет важно |
|---|---|---|
| Трафик в LAN не шифруется (HMAC даёт целостность, но не секретность) | TLS с самоподписанным сертификатом и pinning — отдельная инфраструктура; в домашней сети и WG-туннеле риск низкий | перейти на HTTPS + pin сертификата в агенте |
| Код привязки — долгоживущий секрет в открытом виде | нужен для провижининга без сервера | TTL кода и одноразовая выдача, PIN на экран привязки |
| На консоли нет PIN/биометрии | сценарий «свой телефон в своей семье» | PIN на запуск и на опасные действия |
| Ребёнок может перепривязать агент на свой сервер в домашней сети | приватный адрес проходит проверку; экран привязки не защищён PIN | PIN администратора на привязку/сброс |
| `wipe`/`reboot` выполняются по подписанной команде без подтверждения на устройстве | команды идут только от консоли родителя | диалог подтверждения на агенте |
| Секрет устройства можно посмотреть в консоли (экран ребёнка) | нужен для перепривязки | скрывать по умолчанию, `FLAG_SECURE` на диалоге |
| `InsecureBaseConfiguration` в lint: cleartext разрешён глобально | адреса LAN произвольны, `domain-config` по IP не масштабируется | сузить после перехода на TLS |

## Проверка

```bash
sh tools/test.sh        # 34 проверки протокола, включая подпись ответов
gradle lintRelease      # 0 error/fatal; warning'и перечислены выше
```

Смоук на устройстве:

1. Подменить ответ: поднять на домашнем IP «консоль» без секрета и вписать её
   код в агент → агент должен писать «ответ без подписи» и не менять политику.
2. Вписать в код привязки `8.8.8.8` → отказ «только адрес домашней сети».
3. Снаружи (мобильный интернет без WG) `curl http://<ip>:8787/api/v1/ping` →
   соединение закрывается, ответа нет.
4. Отправить с ПК 40 заголовков → `431`, соединение закрыто.

## Что не покрыто

Аудит был статическим (чтение кода), без динамических тестов и без запуска на
телефоне. Первый реальный прогон — после установки консоли 1.4.0 и агента
1.3.0 по `docs/OPERATIONS.md`.
