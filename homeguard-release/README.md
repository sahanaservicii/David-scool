# HomeGuard

Родительский контроль, который не уходит в облако.

HomeGuard — офлайн-комплект из двух Android-приложений и локального протокола:
агент с правами Device Owner на телефоне ребёнка и консоль на телефоне родителя.
Управление идёт по домашней сети или через WireGuard на домашнем роутере.

## Зачем

Обычные решения родительского контроля требуют аккаунт, подписку и облачный
сервер: состояние устройства и команды проходят через чужую инфраструктуру, а
без интернета контроль исчезает. HomeGuard устроен наоборот:

- ни аккаунтов, ни FCM, ни подписок, ни внешних серверов;
- консоль — это телефон родителя, на нём же работает встроенный HTTP-сервер и
  база SQLite;
- телефон ребёнка сам опрашивает консоль, поэтому не нужны push-сервисы,
  постоянный сокет и проброс портов;
- если связи нет, агент продолжает действовать по последней политике, а
  события копятся и уходят при первом же успешном синке;
- всё, что собирается об устройстве, остаётся в домашней сети.

Это не средство слежки: комплект не читает SMS, звонки, мессенджеры, фото и не
показывает экран ребёнка в реальном времени. Он управляет функциями устройства.

## Возможности

- **Приложения и установки.** Блокировка списка пакетов, запрет установки,
  удаления и установки из неизвестных источников.
- **Устройство.** Камера, Wi-Fi, Bluetooth, USB-передача, скриншоты,
  статус-бар, keyguard, безопасный режим, сброс к заводским настройкам,
  отладка. Для аварийного отключения связи — авиарежим.
- **Экранное время.** Дневной лимит и отчёты по приложениям на основе
  `UsageStatsManager`.
- **Расписание.** Окна «тихого часа» по дням недели, проверка раз в минуту;
  ручная разблокировка даёт 30 минут тишины расписанию.
- **SOS.** Кнопка на главном экране агента отправляет сигнал и координаты
  событием в консоль и высокоприоритетное уведомление родителю. SOS доступен
  и на экране блокировки.
- **Блокировка экрана и киоск.** `lockNow()`, полноэкранный overlay в lock task
  mode, выход — только командой из консоли; режим киоска через
  `setLockTaskPackages`.
- **Геолокация.** Разовый запрос координат по команде, без фонового трекинга.
- **Данные.** Локальная резервная копия и восстановление, версионируемая схема
  базы, автоматическая ретенция событий и статистики, локальный лог сбоев
  (подробнее — [docs/OPERATIONS.md](docs/OPERATIONS.md)).
- **Настройка.** Чек-лист из девяти пунктов работает как мастер первого
  запуска и показывает готовность устройства к защите.

## Архитектура

```
     телефон ребёнка                             ваш телефон
  ┌───────────────────────┐             ┌──────────────────────────────┐
  │ Агент 1.3.0           │             │ Консоль 1.4.0                │
  │ Device Owner (DPC)    │  POST /sync │ Нативное приложение          │
  │ Политика, ограничения │ ──────────▶ │ HTTP-сервер 0.0.0.0:8787     │
  │ Планировщик 60/120 с  │ ◀────────── │ SQLite: дети, правила,       │
  │ Foreground sync, SOS  │  policy +   │ команды, события, статистика │
  │ Curfew overlay        │  commands   │ Уведомления                  │
  └───────────────────────┘             └──────────────────────────────┘
              ▲                                  ▲
              └────── WireGuard, 192.168.9.2 ────┘

  LAN: консоль 192.168.1.10:8787   |   вне дома: консоль 192.168.9.2:8787
```

Модель **pull**: агент сам опрашивает консоль раз в 60 с в Wi-Fi и раз в 120 с
в мобильной сети, тело запроса ~1–3 КБ. На смену сети он реагирует сразу, backoff
ограничен 4 минутами, необработанные события не теряются.

Готовые APK лежат в `dist/`: `agent-1.3.1.apk` и `console-1.4.1.apk`. Контрольные
суммы — `dist/SHA256SUMS`.

## Быстрый старт

Пошаговый чек-лист установки и привязки: [docs/QUICKSTART.md](docs/QUICKSTART.md).

Установка требует подготовки: чтобы выдать агенту права Device Owner, телефон
ребёнка нужно сбросить к заводским настройкам и подключить его по ADB: задача
не сводится к одному нажатию. Данные с телефона ребёнка сохраните заранее.

1. **Сборка.** Возьмите готовые APK из `dist/` или соберите их самостоятельно —
   [docs/BUILD.md](docs/BUILD.md) и раздел «Сборка и тесты» ниже.
2. **Консоль.** Установите `dist/console-1.4.1.apk` на свой телефон, откройте
   его и разрешите уведомления. На экране должно быть
   `Сервер: http://192.168.1.10:8787` и состояние «сервер работает». Нажмите
   «Проверить сервер». Не закрывайте приложение: этот телефон и есть сервер;
   для консоли включите «Без ограничений» в настройках батареи.
3. **Привязка через QR (простой путь).** В консоли: «Добавить ребёнка» → имя.
   Консоль покажет **крупный QR-код** со всей строкой привязки. На телефоне
   ребёнка откройте агент → «Сканировать QR» → наведите камеру на этот код,
   держа экран ровно. Код подставится сам — остаётся нажать «Сохранить
   привязку» и подтвердить адрес консоли. Разрешение камеры запрашивается при
   первом сканировании.

   Если камера не сработала — та же строка продублирована текстом под QR; её
   можно ввести вручную в поле «Код привязки» (запасной путь):

   ```
   hg1:192.168.1.10+192.168.9.2:8787:kid-ab12:<КОД>
   ```

   Код создаётся консолью в момент привязки. Адрес в строке — только приватный
   IPv4; второй адрес через `+` необязателен и нужен для WireGuard.
4. **Агент и Device Owner.** После сброса телефона ребёнка, до добавления
   аккаунтов и второго пользователя, с ПК в той же сети выполните:

   ```bash
   adb devices
   adb install -r dist/agent-1.3.1.apk
   adb shell dpm set-device-owner ru.homeguard.agent/.GuardReceiver
   ```

   Ожидаемый вывод: `Success: Device owner set to package ComponentInfo{...}`.
   Если `dpm` сообщает о существующих аккаунтах — повторите сброс и не
   добавляйте аккаунт до команды. Подробности и альтернативный путь —
   [docs/PROVISIONING.md](docs/PROVISIONING.md).
5. **Разрешения.** Откройте агент и пройдите чек-лист «Настройка» сверху вниз.
   Защита стартует автоматически при открытии приложения.

| Пункт чек-листа | Что сделать |
|---|---|
| Права владельца | Уже выданы командой `dpm`; статус «Готово» |
| Привязка к консоли | Вставить строку из шага 3 → «Сохранить привязку» |
| Уведомления | Разрешить |
| Геолокация | Разрешить (владельцу устройства выдаётся сразу) |
| Статистика использования | HomeGuard → разрешить |
| Специальные возможности | HomeGuard → включить |
| Поверх других приложений | Разрешить для overlay-блокировки |
| Батарея | «Без ограничений» |
| Отладка по USB | Выключить после настройки |

Когда все девять пунктов отмечены, шапка показывает «Защита включена».
Проверка: в течение двух минут устройство становится онлайн в консоли,
приходят батарея и экранное время; команда «Заблокировать экран» гасит экран,
«Разблокировать» возвращает рабочий стол.

Закрепите адрес консоли в DHCP-резервации роутера: агент запоминает адрес из
строки привязки и сам переключается только между двумя адресами из неё.

## Работа вне дома через WireGuard

Туннель на домашнем роутере заменяет проброс портов. Консоль слушает
`0.0.0.0:8787`, поэтому доступна и по адресу в туннеле — `192.168.9.2`. Порт
8787 не нужно открывать наружу: DNAT, UPnP и DMZ не используются.

На обоих телефонах включите WireGuard с split tunnel — в туннель идёт только
домашняя подсеть:

```
[Peer]
Endpoint = console.example.org:<порт>
AllowedIPs = 192.168.9.0/24
PersistentKeepalive = 25
```

`console.example.org` здесь — пример имени WireGuard-пира на роутере; в строке
привязки допустимы только IP-адреса. Остальной трафик идёт напрямую через
Wi-Fi или мобильную сеть: скорость и расход батареи не меняются.

- Включите «Always-on VPN» на обоих телефонах, но **не** ставьте галочку
  «Блокировать соединения без VPN» — иначе при обрыве туннеля у ребёнка
  пропадёт интернет.
- Для агента и WireGuard включите «Без ограничений» в настройках батареи:
  агрессивные прошивки выгружают VPN и фоновую синхронизацию.
- Проверьте канал до установки агента — с телефона ребёнка в браузере:

  ```
  http://192.168.9.2:8787/api/v1/ping
  → {"ok":true,"app":"homeguard-console","port":8787}
  ```

Если ответ пришёл, канал рабочий. Если устройства — пиры одной WireGuard-сети
или на роутере есть маршрут к адресу консоли, привязка заведётся; дома агент
выберет LAN-адрес, вне дома — адрес в туннеле.

## Протокол и безопасность

Все запросы к консоли подписываются HMAC-SHA256 секретом устройства. Секрет
генерируется при привязке и хранится в Android Keystore.

```
X-HG-Device: kid-ab12
X-HG-Ts:     <unix time>
X-HG-Nonce:  <hex, 16–64 символа>
X-HG-Sig:    HMAC(secret, "POST\n<path>\n<ts>\n<nonce>\nSHA256(body)")
```

| Маршрут | Назначение |
|---|---|
| `POST /api/v1/sync` | Состояние устройства и события → политика и очередь команд |
| `POST /api/v1/ack` | Подтверждение выполнения команды |
| `GET /api/v1/ping` | Проверка живости сервера, без подписи |

Консоль подписывает и свои ответы; агент проверяет подпись, временное окно и
повтор nonce до разбора JSON — политика и команды из неподписанного ответа
игнорируются:

```
X-HG-Ts:    <unix time>
X-HG-Nonce: <hex>
X-HG-Sig:   HMAC(secret, "RESP\n<path>\n<ts>\n<nonce>\nSHA256(body)")
```

- Временное окно — ±300 с; nonce хранится 10 минут, кэш ограничен 10 000
  записей.
- Политика версионируется: агент применяет только более новую версию. Команды
  идемпотентны по 128-битному `id` и повторяются, если подтверждение не пришло
  за 10 минут; подтверждение привязано к устройству.
- Сервер отвечает только приватным адресам-источникам и ограничивает запрос:
  тело до 64 КБ, до 32 заголовков и 16 КБ на них, строка до 4 КБ, дедлайн 15 с.
- Экран кода привязки защищён от скриншотов; приложения не пишут логи.

Остаточные риски приняты осознанно: трафик внутри LAN не шифруется (HMAC даёт
целостность и подлинность, но не конфиденциальность — для шифрования канала
служит WireGuard), на консоли нет блокировки запуска, код привязки долгоживущий,
команды блокировки и перезапуска не требуют подтверждения на устройстве.
Полная модель угроз, закрытые пункты и способы проверки —
[docs/SECURITY.md](docs/SECURITY.md).

## Сборка и тесты

```bash
sh tools/build.sh            # сборка релизов, копирование в dist/, SHA256SUMS
sha256sum -c dist/SHA256SUMS # проверка готовых APK
sh tools/test.sh             # 34 проверки протокола, без JUnit, сети и устройства
```

Сборка через Gradle напрямую:

```bash
gradle assembleRelease --no-daemon
gradle lintRelease
```

`tools/build.sh` проверяет подпись готовых APK через `apksigner`. Тесты
проверяют совместимость протокола агент ↔ консоль, вектор HMAC, подпись
ответов и обработку nonce. Процедуры обновления и отката —
[docs/OPERATIONS.md](docs/OPERATIONS.md).

## Требования

| Что | Версия |
|---|---|
| Телефоны | Android 13–15 (`minSdk 33`, `targetSdk 34`) |
| SDK | Android SDK 34, build-tools 34.0.0 |
| Исходный код | Java 17 (`sourceCompatibility` / `targetCompatibility`) |
| Тулчейн сборки | JDK 21 (AGP вызывает `jlink`), Gradle 8.7, AGP 8.5.2 |
| Среда | офлайн-сборка после однократной установки инструментов |

Сборка не обращается к интернету: зависимости и SDK устанавливаются заранее.
На некоторых архитектурах `aapt2` запускается через qemu — детали в
[docs/BUILD.md](docs/BUILD.md).

## Ограничения платформы

- Доступ к статистике использования (`PACKAGE_USAGE_STATS`) выдаётся вручную
  один раз.
- Разрешение «Поверх других приложений» (`SYSTEM_ALERT_WINDOW`) желательно для
  overlay: без него поведение различается между прошивками.
- `WifiManager.setWifiEnabled` закрыт для сторонних приложений с Android 10,
  поэтому отключение связи реализовано через авиарежим или запрет изменения
  настроек.
- Некоторые прошивки агрессивно останавливают фоновые службы: нужны «Без
  ограничений» для батареи и автозапуск.
- Безопасный режим и физический доступ к кнопкам не перекрываются на 100 %;
  Device Owner закрывает большую часть путей, но не заменяет контроль доступа
  к самому устройству.
- Без связи (ни Wi-Fi, ни мобильной, ни туннеля) синхронизации нет: политика
  продолжает действовать локально, события уходят позже.
