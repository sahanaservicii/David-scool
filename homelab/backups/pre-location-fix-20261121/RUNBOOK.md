# RUNBOOK: типовые сбои

Все команды — с телефона в домашней сети. Начни с:

```bash
cd homelab
python3 homelab.py doctor
```

## 1. Home Assistant недоступен

1. `python3 homelab.py doctor` — смотреть строку «Home Assistant».
2. Если `:8123` не открыт: проверить питание HA-хоста и Wi-Fi.
3. Если порт открыт, но API молчит: проверить токен
   (`~/.config/opencode/secrets/homelab.env`), затем `ha config`.
4. Ошибки: `python3 homelab.py ha errors`.
5. Перезапуск HA — только вручную/с подтверждением, после `check_config`.
6. Извне (2026-11-17 добавлен DNAT): `WAN TCP 18443 → 192.168.1.156:8123`,
   только с источника `91.79.32.179/32`. Быстрая проверка:
   `curl -s -o /dev/null -w '%{http_code}\n' http://sahanovschi.v6.rocks:18443/api/`
   — код 401 означает, что проброс и сам HA отвечают. Код 000 — проверять
   whitelist (сменился публичный IP телефона) и firewall на роутере.
   Канал без TLS; предпочтительный доступ — WireGuard, DNAT только для этого IP.
   Подробности и откат — в `CHANGELOG.md`, запись 2026-11-17.

## 2. Роутер не отвечает по SSH

1. `homelab.py doctor` → «Роутер SSH».
2. Проверить, что телефон в сети `192.168.1.0/24` (`homelab.py scan`).
3. Проверить ключ: `ls -l ~/.ssh/`, `ssh -v root@192.168.1.1`.
4. Если SSH закрыт, но Wi-Fi работает — LuCI `http://192.168.1.1`
   (доступ всей LAN; лучше ограничить).
5. Полная потеря доступа — failsafe: выключить питание, включить, быстро
   подключиться по Ethernet к `192.168.1.1`, действовать по инструкции OpenWrt.
   Без понимания шагов не выполнять.

## 3. Android TV не управляется

1. `python3 homelab.py tv devices` — reachable/ADB.
2. Если `reachable: false` — проверить питание и Wi-Fi приставки.
3. Если ADB выключен — включить «Отладка по сети» в настройках разработчика.
4. Если «требуется авторизация» — подтвердить ключ на экране ТВ.
5. После работ выключить ADB (команда в skill `android-local`).

## 4. Камера/NVR пропала

1. `python3 homelab.py cam <ip>`.
2. Проверить питание/PoE и порт на NVR.
3. Проверить, не изменился ли IP: `homelab.py scan`, DHCP-аренды.
4. Проверить VLAN/firewall, если камеры изолированы.
5. Не сбрасывать камеру в заводские настройки без бэкапа конфигурации.

## 5. Нет интернета, но LAN работает

1. `homelab.py router status` — WAN-интерфейс, uptime.
2. `homelab.py router exec "logread | tail -50"`.
3. Проверить WAN-кабель/провайдера, DNS.
4. Не открывать пробросы и не менять firewall «для проверки».

## 6. Нужно откатить изменение

- Роутер: `homelab.py router backup` перед изменениями; восстановление —
  `sysupgrade -r /tmp/<backup>.tar.gz` (вручную, разрушительно).
- HA: копия JSON автоматизации в `/tmp`; полный снапшот HA — через UI.
- Локальные конфиги: `homelab.py backup`, архивы в `backups/`.

## 7. Телефон вне дома

`doctor` покажет недоступность LAN — это нормально. Локальные функции
(уведомления, буфер, файлы) работают; управление роутером/HA/ТВ — только
из домашней сети или через WireGuard (если настроен).

## 8. Синхронизация контактов Google между телефонами

Телефоны: POCO `192.168.1.155` (`phone`), HONOR X5c Plus `192.168.1.138`
(`honor-138`), realme 10 `192.168.1.241` (`realme-241`).

Ограничения, проверено 2026-11-16:
- среда офлайн, до API Google доступа нет — включить синхронизацию может
  только пользователь в самом телефоне;
- ADB по TCP на всех трёх выключен (`:5555` не отвечает), поэтому настройки
  аккаунтов удалённо не читаются;
- в `homelab.json → android` заведены только `tv` и `phone` (155). Для 138 и
  241 `--target` по имени не работает — указывать IP.

### 8.1 Почему контакты не переходят (чек-лист по каждому телефону)

1. Один и тот же Google-аккаунт на всех трёх. Проверить адрес аккаунта:
   Настройки → Пароли и аккаунты → Google (на MIUI/HyperOS — «Аккаунты и
   синхронизация», на HONOR/realme — «Пользователи и аккаунты» / «Аккаунты
   Google»; если пункт не находится — поиск «аккаунт» в настройках).
2. В этом же экране у аккаунта Google включён тумблер **«Контакты»**
   (и «Люди»/«Google Контакты», если отдельным пунктом).
3. Приложение «Контакты» имеет разрешение на контакты: Настройки →
   Приложения → Контакты → Разрешения → «Контакты» = разрешено.
4. Оно же не ограничено в фоне: Настройки → Приложения → Контакты →
   Батарея → «Без ограничений» (не «Оптимизировать»).
5. Новый контакт сохраняется в **Google**, а не в «Телефон»/«SIM»: в форме
   создания контакта открыть список мест сохранения и выбрать аккаунт.
   Контакты, уже лежащие в «Телефон», сами не синхронизируются.
6. MIUI/HyperOS (POCO 155): Настройки → Приложения → Контакты и синхронизация
   → Автозапуск = вкл, Батарея → «Без ограничений»; плюс то же для
   «Сервисы Google Play». Отключить общий режим энергосбережения.
7. HONOR/realme (138, 241): те же два пункта — автозапуск/фон для «Контакты» и
   «Сервисы Google Play», батарея без ограничений.

### 8.2 Проверка, что аккаунт реально пишется в контакты

1. На телефоне A создать тестовый контакт с явным именем (например,
   `ZZ-test-sync`) и сохранить именно в Google-аккаунт (шаг 8.1.5).
2. Оставить телефон A в сети и с включённой передачей данных на 5–15 минут,
   приложение «Контакты» открыть один раз.
3. На телефоне B: Настройки → Пароли и аккаунты → Google → «Синхронизировать
   сейчас», затем открыть «Контакты» и поиском найти `ZZ-test-sync`.
4. Есть на B — канал рабочий, дело было в шагах 8.1.3–8.1.7 на одном из
   телефонов. Нет на B — переходить к 8.3.
5. Тестовый контакт удалить и дать синхронизации пройти.

Веб-версию Контактов Google не использовать: доступа в интернет из этой среды
нет.

### 8.3 Нет тумблера «Контакты» или синхронизация падает с ошибкой

Сначала сохранить данные, только потом трогать аккаунт.

1. Экспорт: «Контакты» → меню → «Импорт/экспорт» → «Экспорт в файл .vcf»,
   файл сохранить в «Загрузки». Переименовать по телефону:
   `poco.vcf`, `honor.vcf`, `realme.vcf`.
2. Убедиться, что файл не пустой: `python3 /root/workspace/homelab/contacts.py
   stats /path/poco.vcf`.
3. Проверить дату/время: Настройки → Система → Дата и время → «Автоматически».
   Неверное время ломает вход в аккаунт.
4. Проверить свободное место (нужно хотя бы несколько сотен МБ).
5. Очистить кэш (не «данные»!): Настройки → Приложения → «Контакты» →
   Память → «Очистить кэш». То же для «Сервисы Google Play» и «Google
   Контакты».
6. Если тумблера «Контакты» нет вообще: удалить аккаунт Google на этом
   телефоне и добавить заново тем же адресом, затем повторить 8.1.2.
   Перед удалением ещё раз проверить шаг 1–2 (экспорт лежит и открывается).
7. Перезагрузить телефон, открыть «Контакты», дождаться синхронизации,
   повторить 8.2.
8. Если после повторного добавления аккаунта синхронизация всё равно падает —
   не сбрасывать телефон; зафиксировать текст ошибки и время, дальше только
   ручной перенос по 8.4.

### 8.4 Резервный путь без Google (локально, офлайн)

1. На каждом телефоне: «Контакты» → меню → «Импорт/экспорт» → «Экспорт в
   файл .vcf» → сохранить в «Загрузки».
2. Забрать файлы на машину с инструментами (USB/локальный мост, облако не
   нужно). Пусть это будут `a.vcf` (POCO), `b.vcf` (HONOR), `c.vcf` (realme).
3. Посмотреть, что внутри и сколько дублей:
   `python3 /root/workspace/homelab/contacts.py stats a.vcf b.vcf c.vcf`
4. Слить в один файл без дублей (склейка по телефону/e-mail):
   `python3 /root/workspace/homelab/contacts.py merge -o merged.vcf a.vcf b.vcf c.vcf`
5. Проверить результат: `python3 /root/workspace/homelab/contacts.py stats merged.vcf`
   — число карточек должно быть меньше суммы входных.
6. Импортировать `merged.vcf` на каждый телефон: «Контакты» → меню →
   «Импорт/экспорт» → «Импорт из файла .vcf», место — «Телефон» (локально,
   без Google), затем вручную удалить старые дубли, если всплывут.
7. Это разовый перенос, а не постоянная синхронизация: при правках на двух
   телефонах повторить 8.4.

### 8.5 Если нужна удалённая проверка по ADB (что сделать пользователю)

1. На телефоне: Настройки → О телефоне → 7 раз нажать «Номер сборки» →
   появились «Для разработчиков».
2. Настройки → Система → Для разработчиков → включить «Беспроводная отладка»
   (на старых прошивках — «Отладка по USB» + `adb tcpip 5555`). Телефон и
   машина с инструментами — в одной сети `192.168.1.0/24`.
3. Проверить: `python3 homelab.py phone devices` (показывает только устройства
   из `homelab.json`), затем точечно по IP:
   `python3 homelab.py phone --target 192.168.1.138 shell "pm list packages | grep -i contact"`
4. По имени 138 и 241 пока не работают — `--target honor-138` вернёт
   «неизвестное Android-устройство». Либо указывать IP, либо (отдельной
   задачей) добавить телефоны в `homelab.json → android`.
5. После работ «Беспроводную отладку» выключить: постоянный ADB — риск.

Проверка, что раздел на месте:

```bash
grep -n "Синхронизация контактов Google" /root/workspace/homelab/RUNBOOK.md
```

## Нет интернета у всех устройств LAN / через WireGuard (fw4 не запускается)

**Симптом:** роутер сам в интернет ходит (ping 1.1.1.1 с роутера ок), а все
LAN-клиенты и WG-клиенты — без интернета. В `wg show` handshake есть, трафик
идёт, но сайты не открываются.

**Причина (найдено 2026-11-17):** в `/etc/config/firewall` остался пустой
раздел `config include` без `option path`. Из-за него `fw4 check` падал
(`Section @include[0] option 'path' is mandatory but not set`), firewall не
стартовал, таблицы `inet fw4` не было вообще → **не работал masquerade (NAT)**
и фильтрация. В `nft list ruleset` была только таблица `xrayredir`.

**Диагностика:**
```sh
fw4 check                      # должен быть "Ruleset passes nftables check."
nft list tables                # должна быть table inet fw4
nft list chain inet fw4 srcnat_wan   # должна быть строка masquerade
```

**Исправление:**
```sh
sysupgrade -b /tmp/cfg-$(date +%F-%H%M).tar.gz   # бэкап
uci delete firewall.@include[0]
uci commit firewall
fw4 check && /etc/init.d/firewall restart
nft list tables | grep fw4
```

**Проверка:** в `conntrack -L` у LAN-клиентов появляются ESTABLISHED-сессии,
где ответ идёт на `dst=172.25.213.7` (адрес WAN) — значит NAT работает.

**Примечания по этому роутеру (Rahmaninova-49, AX3600, OpenWrt 25.12.5):**
- Доступ: SSH по паролю на WAN-адресе (порт 22 проброшен), ключ
  `~/.ssh/id_ed25519` на роутер **не** установлен.
- WAN: `172.25.213.7/24` (за NAT провайдера), LAN `192.168.1.1/24`,
  WG `192.168.9.1/24` (peer phone `192.168.9.2/32`).
- В firewall есть лишняя зона `wg`, в которую ошибочно добавлены интерфейсы
  `lan`/`wan` (дублирование зон). Работает, но лучше удалить.
- `wan` input = ACCEPT и парольный root-SSH на WAN → в логах постоянный
  брутфорс. Нужно закрыть (оставить только LAN/WG или ключи).
- `/etc/rc.local` поднимает таблицу `xrayredir`: весь LAN TCP 80/443
  редиректится в xray `:12345` (proxy только для YouTube, остальное direct).

### Автостраховка firewall (с 2026-11-17)

На роутере стоит сторож `/usr/local/sbin/fw-watchdog.sh` (cron каждые 5 минут):
1. проверяет `fw4 check`, наличие `table inet fw4` и `masquerade` в `srcnat_wan`;
2. если firewall не поднят — перезапускает его;
3. если конфиг битый (например, пустой `config include`) — откатывает
   `/etc/config/firewall` из эталона `/root/fw-good/firewall` и перезапускает;
4. пишет в `/root/fw-good/watchdog.log` и syslog (`log -t fw-watchdog`);
5. дополнительно проверяет ping 1.1.1.1 и DNS через dnsmasq.

Эталон обновляется автоматически, когда конфиг проходит проверку.
Проверка вручную:
```sh
/usr/local/sbin/fw-watchdog.sh; tail -5 /root/fw-good/watchdog.log
```

Ежедневный бэкап конфига: `15 4 * * *` → `/root/backups/cfg-YYYY-MM-DD.tar.gz`,
хранится 7 последних.

### WireGuard: клиентский профиль phone2 (2026-11-17)

Добавлен второй peer: `192.168.9.3/32`, описание `phone2`, PSK.
Готовый конфиг для импорта: `/root/workspace/homelab/wg-phone2.conf`.
Endpoint: `sahanovschi.v6.rocks:51820`, AllowedIPs `0.0.0.0/0` (IPv6 в туннель
не заводим — у провайдера его нет). Существующий peer `phone` (`192.168.9.2/32`)
не тронут.

`homelab.json`: `router.host` = `sahanovschi.v6.rocks`, доступ по ключу
`~/.ssh/id_ed25519` (ключ установлен на роутер), `homelab.py router status`
работает.
