# Дубликат пропуска детского сада — рабочие шаги

## Текущее состояние (проверено 2026-11-20)
- UID сохранён: `state/cards/kindergarten.uid.txt` (7 байт / 14 HEX, отпечаток `49441c54b1dc`).
- **Подтверждено пользователем:** `ISO/IEC 14443 Type A` → 13.56 МГц, HF. Ветка 125 кГц (LF) отпадает, нужен эмулятор HF.
- **Подтверждено пользователем:** `MIFARE Classic`, UID 7 байт, каскадирование `CL1 + CL2`. Уточняется только объём (`1K` / `4K`) — устройство покажет при чтении.
- Важно: 7-байтовый UID требует поддержки двух уровней каскадирования. Эмулятор, умеющий только 4-байтовый UID (CL1), такую карту не воспроизведёт — при покупке уточнять поддержку 7-byte UID.
- Секторы могут быть защищены ключами: подбор ключей не делаем. Если дамп не читается — пробуем эмуляцию по одному UID (работает не у всех считывателей).
- В этой среде нет ридера/писателя: USB/serial, libnfc/pcsc, NFC-API в мосте и ADB отсутствуют.
- Разрешение сада на копирование — по словам пользователя. Только свой/выданный ребёнку пропуск.

## Шаг 0 — срочно, сегодня (самый быстрый и надёжный)
Позвонить/написать в администрацию сада и попросить **официальный второй пропуск на ребёнка**.
Это единственный путь, который гарантированно работает сегодня без покупки железа.

## Шаг 1 — измерить тип (только чтение, 2 минуты)
На POCO: **NFC TagInfo by NXP** или **MIFARE Classic Tool** → приложить пропуск → скопировать строку `Tech` / `Technologies`.

| Что показывает | Диапазон | Что дальше |
|---|---|---|
| `MIFARE Classic` | 13.56 МГц | эмулятор HF / дамп + magic-карта |
| `MIFARE Ultralight`, `NTAG213/215/216` | 13.56 МГц | эмулятор HF проще |
| `ISO-DEP`, `ISO 14443-4` | 13.56 МГц | нужна логика приложения вендора |
| приложение ничего не видит | вероятно 125 кГц | нужен LF-эмулятор (не PN532) |

Type A уже подтверждён — строка «приложение ничего не видит» неактуальна. Дальше важна вторая строка в выводе приложения: `MIFARE Classic` / `Ultralight` / `NTAG` / `ISO-DEP`.

## Шаг 2a — Flipper Zero (универсальнее: HF + LF)
Лучше не вбивать UID вручную, а считать карту самим Flipper — так сохранится полный дамп.

**13.56 МГц, MIFARE Classic:**
1. `NFC` → `Read` / `Read card` → приложить пропуск → дождаться успеха. Устройство само покажет `1K`/`4K` и считает UID.
2. `Save` → имя, например `kindergarten`. Файл появится на microSD в `nfc/`.
3. `Saved` → `kindergarten` → `Emulate` → поднести к турникету сада.
4. Если полный дамп не прочитан из-за ключей — создать карту только с сохранённым UID и проверить её; это fallback, не гарантия.

**125 кГц:**
1. `RFID` → `Read` → приложить пропуск → `Save` как `kindergarten`.
2. `RFID` → `Saved` → `kindergarten` → `Emulate`.

Сверка: считанный UID должен совпасть с сохранённым в `state/cards/kindergarten.uid.txt`.

## Шаг 2b — Chameleon Ultra (только если тип подтверждён как HF и важна совместимость со СКУД)
1. Подключить устройство к приложению **Chameleon Ultra** по Bluetooth (офлайн, без облака).
2. `Scan / Read` → приложить пропуск → сохранить результат в свободный слот.
3. Переключить активный слот на сохранённый (кнопкой или в приложении) — устройство переходит в режим эмуляции.
4. Поднести к турникету сада. Поддержку 125 кГц уточнять по конкретной ревизии/прошивке устройства.

## Шаг 3 — проверка
- Проводить только на своём пропуске и с разрешения сада.
- Если турникет не открывается: скорее всего он проверяет зашифрованные секторы, а не только UID — тогда нужен полный дамп с ключами или официальный дубликат.
- **Не подбирать ключи MIFARE и не обходить СКУД.**

## Ограничения
- Прошить/настроить устройство из этой офлайн-среды нельзя — нет toolchain и самого устройства.
- Устройство нужно приобрести локально; цикл «считать → сохранить → эмулировать» делает пользователь на телефоне/устройстве.
- UID уже был опубликован в переписке — не распространять его дальше.
